# 自然月朗读礼包变更

## 规则

| 身份 | 标准字数 | 精品字数 |
| --- | ---: | ---: |
| 月度 | 0 | 0 |
| 年度 | 5000 | 2500 |
| 永久 | 8000 | 4000 |
| 永久超级 | 12000 | 6000 |

北京时间每月 1 日 00:00 至次月 1 日 00:00（不含），标准/精品二选一。每个账号每个自然月最多一份；升级、续费、断档后同月重新开通都不能重复领取。领取时检查当前有效权益、覆盖当前时间的商品及退款欠款。月底开通可领当月，次月刷新；错过月份不补领。

用户已确认：已领字数继续累计，不在月底清零。续费延长同一连续会员周期内的额度有效期，升级永久可长期使用，已经到期的旧周期额度不因新周期复活。会员有效期仍使用原开通日锚点。后续用户已确认云下载也改自然月，切换当月重新提供 1 GiB，详见 [统一自然月额度](calendar-allowances.md)。

## 历史兼容

- 迁移 021 只新增可空的 `gift_month` 和索引，不改写已有领取、字数、流水或有效期。
- 新领取使用绝对北京时间月份索引（年 × 12 + 月份零基数）；数据库唯一约束为账号＋月份，事务沿用账号与 TTS 额度锁。
- 历史记录 `gift_month` 为空，按 `created_at` 所在的北京时间自然月查询。同月已领取旧额度的账号不会重复领取或补差额；客户端展示实际已领字数。
- 历史上一个自然月内存在两份旧权益月礼包时，保留两份，不追扣；页面展示最早的一份，阻止该月再领。
- 快照新增 `giftCycle`，原 `cycle` 保留旧开通日周期供兼容；云下载接口自行使用自然月。新版 App 使用 `giftCycle` 展示领取日期，日期固定北京时间，并把排他的次月零点展示为当月最后一天。
- 旧版 App 的礼包日期/权益对比文案可能仍是旧规则，应同步发布新版 App；实际发放由服务端决定。

## 发布

本次在本地完成代码、迁移和安装包验证，尚未执行生产迁移或部署。

1. 备份数据库和现有 `membershipPolicy.js`、`membershipService.js`。停止旧服务后执行迁移，避免新旧领取规则同时写入。
2. 当前工作区的会员服务还包含开售时间/活动价能力（先前工作），部署本次两个模块前，线上必须已有 `membershipSales.js`、迁移 016 的会员表和迁移 019 的开售/活动价表结构；缺少前置条件时先完成相应发布，不直接覆盖。
3. 用 `psql -v ON_ERROR_STOP=1` 执行 `021_membership_calendar_gifts.sql`，再替换两个编译模块并启动服务。此迁移可重复执行，不会修改已有额度。
4. 发布随包 HAP，检查三档额度、北京时间月末日期、旧领取保持已领取、月度无礼包、云下载截止日期为北京时间下月1日零点。生产账号领取会真实发放额度，优先使用测试账号。
5. 回退时保留新增列/索引，恢复旧模块即可启动；但旧代码不识别新月度记录，可能重复发放，因此回退期间暂停礼包领取，核对当月领取后再恢复服务。
