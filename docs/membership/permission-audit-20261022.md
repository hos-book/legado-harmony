检查范围：本地服务端规则、数据库事务与迁移、客户端权益展示及权限入口。未连接生产数据库、未实际领取生产礼包、未做真机或真实 PostgreSQL 多连接并发复验。

## 礼包检查结果

- 按北京时间自然月领取，每个账号每月标准或精品二选一；月底开通可领当月，次月一日刷新，未领不补发。
- 各档两种额度均检查实际发放字数、额度记录和流水；同档重试仅返回原领取，换档被拒绝。
- 月度续年度需等原月度时段结束才获得年度礼包；年度续月度在年度时段仍可领取，进入月度延长期后不可新领。
- 同月升级或到期重开不再次发放、不补差额；跨月已领字数保留。连续续费延长原周期额度有效期，升级永久使原周期额度长期有效，已到期旧周期不复活。
- 历史领取按实际领取时间归入自然月，保留旧字数；迁移重跑和账号月份唯一约束已有覆盖。
- 免费、未生效、到期和欠款账号不能新领；欠款补齐后恢复权益。非法音色档位被拒绝，失败不写入礼包、额度或流水。
- 礼包发放使用会员账号锁、钱包锁、音色额度锁及事务；账号与月份唯一索引兜底。本轮未重跑真实 PostgreSQL 多连接竞争脚本。

## 修复

`AccountCenter.giftIncluded()` 原来通过展示字数判断当前礼包资格。月度会员保留旧的标准礼包领取记录时，会误把“每月朗读礼包”显示在当前会员权益中；精品旧领取不触发该问题，造成两档展示不一致。

现改为读取当前有效权益，历史领取仅展示实际已领字数，仍保持已领取状态与禁止重复领取。另将未开通会员时的宣传文案明确为年度及终身会员可领礼包。服务端发放规则未改动。
