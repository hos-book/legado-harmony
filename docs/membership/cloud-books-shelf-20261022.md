# 云端书籍与本地书架修复（2026-10-22）

## 原因

云空间手动上传原来只完成云端文件传输，随后清除暂存文件，没有调用本地书籍导入。自动同步又要求云端 BOOK 带有 `meta.contentHash`，因此历史手动上传的 EPUB/TXT 也不会被加入书架。

## 调整

- 手动上传完成后，先使用本机暂存文件导入书架，再清除上传任务和暂存文件，无需再次下载。导入失败保留任务，可继续重试。
- 历史手动上传的 EPUB/TXT 即使没有元数据，也会在启用本地书籍同步后的对账中加入书架，作为待下载的本地书显示；点击阅读时下载并导入。
- 用云文件 ID、内容指纹或分块清单指纹匹配已存在的本地书，复用其书架地址、分组和阅读进度。分块清单指纹不冒充内容指纹。
- 云空间下载入口复用相同导入逻辑，避免与已有占位书重复。云空间刷新成功后调度一次自动同步，旧文件无需重新上传。
- 已下载的历史手动文件通过云文件 ID 关联移除操作；只删除云端副本时保留本地文件。

## 验证

- `node --test scripts/cloud-auto-sync-check.mjs scripts/cloud-transfer-check.mjs`：20 项通过，涵盖无元数据 EPUB、历史文件匹配、上传后导入、重复同步、删除、导入失败重试，以及限流恢复。
- `node scripts/cloud-files-ui-check.mjs`：编译后的云空间用量更新与失败后恢复入口检查通过。
- `assembleHap`：构建签名包成功；本轮未进行真机安装验证。

这部分是客户端修复，不要求修改 PostgreSQL 数据。上传中断对应的服务端限流修复仍按 `cloud-files-fix-20261022.md` 单独部署。
